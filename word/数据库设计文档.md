# 智能打卡系统数据库设计文档

## 📋 设计说明

**设计版本**: v2.0 (简化版)  
**更新日期**: 2025年12月12日  
**设计理念**: MVP（最小可行产品）- 快速开发，满足核心需求，后续可扩展

### 简化原则
1. **功能聚焦**: 专注核心考勤功能，延后非必要模块
2. **结构精简**: 从 13 个表简化为 5 个核心表
3. **易于扩展**: 保留扩展接口，后续可按需添加功能

### 主要简化
- ✅ 打卡方式：仅保留点击打卡（移除人脸识别、GPS等）
- ✅ 角色管理：移除 HR 角色，保留 ADMIN/MANAGER/EMPLOYEE
- ✅ 请假管理：简化为 3 种类型（事假、病假、年假），无需单独类型表
- ✅ 部门管理：扁平化结构，仅一级部门
- ✅ 工作制度：支持固定时间制和弹性工作制
- ❌ 延后功能：加班管理、工作日历、统计表、通知、日志等

## 表结构设计（共 5 个核心表）

### 1. 用户表 (users)

存储系统用户的基本信息。

```sql
CREATE TABLE users (
    id BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '用户ID',
    username VARCHAR(30) NOT NULL UNIQUE COMMENT '用户名',
    password VARCHAR(255) NOT NULL COMMENT '密码（BCrypt加密）',
    email VARCHAR(100) NOT NULL UNIQUE COMMENT '邮箱',
    real_name VARCHAR(50) COMMENT '真实姓名',
    department_id BIGINT COMMENT '部门ID',
    role_id BIGINT NOT NULL DEFAULT 4 COMMENT '角色ID（默认普通员工）',
    status TINYINT DEFAULT 1 COMMENT '状态：0-禁用，1-启用',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    INDEX idx_username (username),
    INDEX idx_email (email),
    INDEX idx_department_id (department_id),
    INDEX idx_role_id (role_id),
    INDEX idx_status (status),
    FOREIGN KEY (department_id) REFERENCES departments(id) ON DELETE SET NULL,
    FOREIGN KEY (role_id) REFERENCES roles(id) ON DELETE SET NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

**字段说明**:
- `id`: 主键，自增（可作为工号使用）
- `username`: 登录用户名，唯一
- `password`: BCrypt加密后的密码
- `email`: 邮箱地址，用于验证码和通知
- `real_name`: 员工真实姓名
- `department_id`: 所属部门外键（可选）
- `role_id`: 角色外键（默认为普通员工）
- `status`: 账号状态（0-禁用，1-启用）
- `created_at`: 创建时间

**简化说明**:
- ❌ 移除 `phone`：初期不需要手机号
- ❌ 移除 `employee_no`：直接使用 `id` 作为工号
- ❌ 移除 `avatar_url`：初期不需要头像功能
- ❌ 移除 `face_feature`：已移除人脸识别功能
- ❌ 移除 `updated_at`, `last_login_at`：非核心字段

### 2. 角色表 (roles)

定义系统中的角色权限。

```sql
CREATE TABLE roles (
    id BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '角色ID',
    role_name VARCHAR(50) NOT NULL UNIQUE COMMENT '角色名称',
    role_code VARCHAR(30) NOT NULL UNIQUE COMMENT '角色编码',
    description VARCHAR(200) COMMENT '角色描述',
    status TINYINT DEFAULT 1 COMMENT '状态：0-禁用，1-启用',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    INDEX idx_role_code (role_code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='角色表';
```

**预设角色（3个）**:
- `ADMIN` (id=1): 系统管理员
  - 所有系统配置权限
  - 所有用户管理权限
  - 全公司数据查看
  
- `MANAGER` (id=2): 部门经理
  - 本部门员工考勤查看
  - 本部门请假审批
  - 本部门考勤统计
  
- `EMPLOYEE` (id=4): 普通员工
  - 个人打卡
  - 个人请假申请
  - 个人考勤记录查看

**简化说明**:
- ❌ 移除 `HR` 角色：权限合并到 ADMIN
- ❌ 移除 `permissions` 字段：权限在代码中控制，简化设计
- ❌ 移除 `updated_at`：非核心字段

### 3. 部门表 (departments)

组织架构的部门信息（扁平化结构）。

```sql
CREATE TABLE departments (
    id BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '部门ID',
    department_name VARCHAR(50) NOT NULL UNIQUE COMMENT '部门名称',
    manager_id BIGINT COMMENT '部门经理ID',
    description VARCHAR(200) COMMENT '部门描述',
    status TINYINT DEFAULT 1 COMMENT '状态：0-禁用，1-启用',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    INDEX idx_manager_id (manager_id),
    INDEX idx_status (status),
    FOREIGN KEY (manager_id) REFERENCES users(id) ON DELETE SET NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='部门表';
```

**字段说明**:
- `id`: 主键，自增
- `department_name`: 部门名称，唯一
- `manager_id`: 部门经理用户ID（外键）
- `description`: 部门描述
- `status`: 状态（0-禁用，1-启用）
- `created_at`: 创建时间

**简化说明**:
- ❌ 移除 `parent_id`, `level`：扁平化结构，无层级关系
- ❌ 移除 `department_code`：直接使用 `id`
- ❌ 移除 `sort_order`：按名称或ID排序即可
- ❌ 移除 `updated_at`：非核心字段
- ✅ 适用场景：中小企业，部门数量不多（<50个）

### 4. 考勤记录表 (attendance_records)

记录每次打卡的详细信息（支持弹性工作制）。

```sql
CREATE TABLE attendance_records (
    id BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '记录ID',
    user_id BIGINT NOT NULL COMMENT '用户ID',
    attendance_date DATE NOT NULL COMMENT '考勤日期',
    check_in_time TIMESTAMP NULL COMMENT '签到时间',
    check_out_time TIMESTAMP NULL COMMENT '签退时间',
    expected_check_out_time TIMESTAMP NULL COMMENT '预期签退时间（弹性模式）',
    check_in_ip VARCHAR(50) COMMENT '签到IP地址',
    check_out_ip VARCHAR(50) COMMENT '签退IP地址',
    work_hours DECIMAL(5, 2) COMMENT '实际工作时长（小时）',
    status TINYINT DEFAULT 1 COMMENT '状态：1-正常，2-迟到，3-早退，4-缺卡',
    is_late TINYINT DEFAULT 0 COMMENT '是否迟到：0-否，1-是',
    is_early_leave TINYINT DEFAULT 0 COMMENT '是否早退：0-否，1-是',
    late_minutes INT DEFAULT 0 COMMENT '迟到分钟数',
    early_leave_minutes INT DEFAULT 0 COMMENT '早退分钟数',
    remark VARCHAR(500) COMMENT '备注',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    INDEX idx_user_id (user_id),
    INDEX idx_attendance_date (attendance_date),
    INDEX idx_user_date (user_id, attendance_date),
    INDEX idx_status (status),
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='考勤记录表';
```

**字段说明**:
- `id`: 主键，自增
- `user_id`: 用户ID（外键）
- `attendance_date`: 考勤日期
- `check_in_time`: 签到时间
- `check_out_time`: 签退时间
- `expected_check_out_time`: 预期签退时间（弹性工作制使用，签到时间+要求工时）
- `check_in_ip`: 签到IP地址（辅助验证）
- `check_out_ip`: 签退IP地址
- `work_hours`: 实际工作时长（小时）
- `status`: 考勤状态
- `is_late`: 是否迟到
- `is_early_leave`: 是否早退
- `late_minutes`: 迟到分钟数
- `early_leave_minutes`: 早退分钟数
- `remark`: 备注（管理员可填写）

**简化说明**:
- ❌ 移除 `check_in_type`, `check_out_type`：仅点击打卡
- ❌ 移除 `check_in_photo_url`, `check_out_photo_url`：无人脸识别
- ❌ 移除 GPS 坐标字段：无GPS定位功能
- ❌ 移除 `check_in_location`, `check_out_location`：简化设计
- ❌ 移除 `check_in_device`, `check_out_device`：非必需
- ❌ 移除 `updated_at`：考勤记录一般不修改
- ✅ 新增 `expected_check_out_time`：支持弹性工作制
- ✅ 新增 `check_in_ip`, `check_out_ip`：简单的位置验证

**弹性工作制说明**:
- 签到时，系统计算 `expected_check_out_time = check_in_time + 要求工时`
- 签退时，根据 `expected_check_out_time` 判断是否早退
- 工作时长 = `check_out_time - check_in_time`

### 5. 请假记录表 (leave_records)

员工请假申请和审批记录（简化版）。

```sql
CREATE TABLE leave_records (
    id BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '请假ID',
    user_id BIGINT NOT NULL COMMENT '用户ID',
    leave_type VARCHAR(20) NOT NULL COMMENT '请假类型：事假、病假、年假',
    start_date DATE NOT NULL COMMENT '开始日期',
    end_date DATE NOT NULL COMMENT '结束日期',
    leave_days DECIMAL(4, 1) NOT NULL COMMENT '请假天数',
    reason VARCHAR(500) NOT NULL COMMENT '请假原因',
    status TINYINT DEFAULT 0 COMMENT '状态：0-待审批，1-已批准，2-已拒绝',
    approver_id BIGINT COMMENT '审批人ID',
    approval_time TIMESTAMP NULL COMMENT '审批时间',
    approval_remark VARCHAR(200) COMMENT '审批备注',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    INDEX idx_user_id (user_id),
    INDEX idx_status (status),
    INDEX idx_date_range (start_date, end_date),
    INDEX idx_leave_type (leave_type),
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
    FOREIGN KEY (approver_id) REFERENCES users(id) ON DELETE SET NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='请假记录表';
```

**字段说明**:
- `id`: 主键，自增
- `user_id`: 申请人用户ID（外键）
- `leave_type`: 请假类型（直接存储字符串）
  - `事假`: 个人事务请假
  - `病假`: 因病请假
  - `年假`: 带薪年假
- `start_date`: 请假开始日期
- `end_date`: 请假结束日期
- `leave_days`: 请假天数（支持 0.5 天）
- `reason`: 请假原因
- `status`: 审批状态
  - `0`: 待审批
  - `1`: 已批准
  - `2`: 已拒绝
- `approver_id`: 审批人用户ID（外键）
- `approval_time`: 审批时间
- `approval_remark`: 审批备注
- `created_at`: 申请时间

**简化说明**:
- ❌ 移除 `leave_types` 表：请假类型直接存储为字符串
- ❌ 移除 `start_time`, `end_time`：按天计算，不需要精确到小时
- ❌ 移除 `proof_url`：初期不需要上传证明材料
- ❌ 移除 `status=3` (已撤销)：简化审批流程
- ❌ 移除 `updated_at`：非核心字段
- ✅ 仅保留 3 种常用请假类型
- ✅ 审批流程简化：待审批 → 已批准/已拒绝

**请假类型说明**:
```
事假: 个人事务，不带薪，无天数限制
病假: 因病请假，带薪，建议提供病假条
年假: 带薪年假，根据公司政策限制天数
```

## 全局配置说明

### 弹性工作制配置（代码配置）

```yaml
# application.yml 或 Java 配置类
attendance:
  work-mode: flexible  # 工作模式：fixed(固定) / flexible(弹性)
  
  # 弹性工作制配置
  flexible:
    check-in-start: "08:00"      # 弹性签到开始时间
    check-in-end: "10:00"        # 弹性签到结束时间
    required-work-hours: 8.0     # 要求工作时长（小时）
    late-tolerance-minutes: 0    # 迟到容忍分钟（10:00后即为迟到）
  
  # 固定时间制配置（备用）
  fixed:
    check-in-time: "09:00"       # 固定上班时间
    check-out-time: "18:00"      # 固定下班时间
    late-tolerance-minutes: 10   # 迟到容忍分钟
    early-leave-tolerance-minutes: 10  # 早退容忍分钟
```

### 工作日规则（代码配置）

```java
// 简单规则：周一至周五工作，周六日休息
public boolean isWorkDay(LocalDate date) {
    DayOfWeek dayOfWeek = date.getDayOfWeek();
    return dayOfWeek != DayOfWeek.SATURDAY && dayOfWeek != DayOfWeek.SUNDAY;
}
```

```sql
-- 创建归档表
CREATE TABLE attendance_records_archive LIKE attendance_records;

INSERT INTO attendance_records_archive 
SELECT * FROM attendance_records 
WHERE attendance_date < DATE_SUB(CURDATE(), INTERVAL 1 YEAR);

-- 删除已归档数据
DELETE FROM attendance_records 
WHERE attendance_date < DATE_SUB(CURDATE(), INTERVAL 1 YEAR);
```

## ER 图关系说明

```
users (用户)
├─ N:1 → roles (角色)
│   └─ 1-ADMIN, 2-MANAGER, 4-EMPLOYEE
│
├─ N:1 → departments (部门) [可选]
│   └─ 扁平化结构，无层级
│
├─ 1:N → attendance_records (考勤记录)
│   └─ 每个用户有多条考勤记录
│
└─ 1:N → leave_records (请假记录)
    ├─ 每个用户有多条请假记录
    └─ approver_id 指向审批人（也是 users）

departments (部门)
├─ 1:N → users (员工)
└─ N:1 → users (经理)
    └─ manager_id 指向部门经理

roles (角色)
└─ 1:N → users (用户)
```

**关系说明**:
- 用户 ↔ 角色: 多对一（每个用户一个角色）
- 用户 ↔ 部门: 多对一（每个用户属于一个部门，可选）
- 用户 ↔ 考勤记录: 一对多（一个用户多条考勤）
- 用户 ↔ 请假记录: 一对多（一个用户多条请假）
- 部门 ↔ 用户: 一对多（一个部门多个员工）
- 部门 ↔ 经理: 多对一（每个部门一个经理）
